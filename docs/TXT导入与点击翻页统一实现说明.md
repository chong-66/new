# 透读：TXT 导入、点击翻页与正文净化统一实现说明

日期：2026-09-10。适用基线：透读 v0.1.4。

本文是三项功能的统一实现依据，替代《TXT导入与自动分章实现说明》和《点击翻页功能实现说明》。交给 GPT-5.6 时只需提供本文。本文描述待实现功能，不代表代码已完成或已通过验证。

## 1. 目标与范围

同时实现：

1. 导入单个 TXT 文件，自动识别章节并保存到应用内部；之后无需原文件，也无需书源即可阅读。
2. 开启自定义点击翻页后，点击正文可见区域上半区向上滚动，下半区向下滚动，用户可设置每次滚动行数。
3. 新增全局正文替换净化规则，用户可删除或替换非正文内容，对网络、缓存与 TXT 生效，并随时恢复净化前原文。

三项功能本身不冲突：TXT 负责提供目录和原文，净化规则生成显示正文，点击翻页负责滚动已显示的正文。必须在同一个 ReaderView 中统一接入，避免各自复制阅读器、各自修改加载流程或各自触发自动下一章。

只实现本功能所需改动。保留现有网络书源、章节缓存、阅读进度、设置兼容性、托盘及窗口行为。安装包、版本号、提交推送和 GitHub 发布依据用户后续指令处理。

首版不做 EPUB/PDF、批量导入、文件拖放、自定义章节正则、文件变动后同步或重新分章、完整备份系统、不同方向分别设置步长，也不改变左右方向键切章的含义。

### 默认值

| 项目 | 默认与约束 |
| --- | --- |
| TXT 文件大小 | 原生端最多 30 MiB（31,457,280 字节），以读取前的原始字节数判断，恰好达到上限允许导入 |
| 编码 | 自动识别，并允许手动选择 UTF-8、GB18030、Big5、UTF-16LE、UTF-16BE |
| 分章方式 | 自动识别；允许手动选择按长度分章 |
| 按长度分章 | 目标约 6000 字符，优先在 4000～8000 字符内寻找合适边界 |
| 单章长度保护 | 超过 20000 字符时继续拆分，保留全部正文 |
| 点击正文翻页 | 默认关闭，升级后保持原有点击行为 |
| 每次滚动行数 | 默认 5 行，允许 1～30 的整数，上下共用 |
| 点击翻页含义 | 按当前正文行高滚动约 N 个视觉行，不是跳过 TXT 的 N 个换行，也不是切换章节 |
| 正文净化 | 默认关闭、规则为空；普通文本/正则全局替换，替换留空表示删除；仅改变显示 |
| 净化作用范围 | 所有书的当前章节正文；不修改目录、原始 TXT 或持久化缓存 |

## 3. 三项功能的统一约定

### 3.1 数据与阅读器职责

- 网络书：继续走现有书源引擎，保留持久化章节缓存、预取、换源、刷新目录和下载缓存面板。
- 本地书：目录来自本地 manifest，正文来自本地章节文件；不进入网络引擎，不要求安装书源。
- 两类书共用全局净化、正文渲染、当前章索引、滚动位置、进度保存、点击滚动、手动切章及现有自动下一章逻辑。
- “本地导入文件”与“网络章节缓存”是两种数据。清理下载缓存不得删除本地书；清空书源不得影响本地书。

### 3.2 阅读状态与交互互斥

统一计算正文是否可交互：已成功加载且非空、没有加载或错误、没有恢复滚动位置、没有覆盖正文的目录/缓存/设置/搜索/TXT 导入/净化规则面板，且不处于幽灵穿透状态。

点击翻页、快捷键和自动下一章均应检查适用于自身的状态。弹窗关闭的同一次点击不能穿透到正文触发翻页。不要依靠事件监听注册顺序解决冲突。

切书、切章、关闭阅读器、打开遮挡面板、失去有效指针手势或加载新正文时，清理点击手势状态。导入面板通常从书架打开，但仍应纳入统一的弹窗互斥约定。

### 3.3 唯一自动下一章入口

点击功能只改变正文容器的 scrollTop，不直接调用下一章。沿用现有 onBodyScroll 对“真实向下滚动并到达底部”的判断和单次锁，避免一次点击切两章。

向上点击不能触发自动下一章；程序恢复进度、换字号、窗口缩放或净化规则变化造成的布局调整，也不能被误认为用户主动向下阅读。本地书和网络书遵循同一规则。

### 3.4 退出与存储

隐藏到托盘沿用现有行为，不视为退出，不另加关闭地址或窗口。真正退出时统一协调章节缓存任务、TXT 导入任务、净化 Worker、规则配置、阅读进度及存储刷新。失败应反馈并允许重试，避免未保存就销毁窗口。

## 4. TXT 导入操作流程

书架有书和无书时都显示“导入 TXT”。首版一次只导入一本；同一时间只允许一个导入任务。

优先使用文件选择 input，限制 .txt/text/plain，并用 File.arrayBuffer 读取原始字节。不能仅依据 MIME 判断，因为 Windows 可能返回空 MIME。若实际 WebView 验证不能满足需求，再引入原生文件选择能力与最小权限，不预先增加不必要依赖。

选择文件后显示：

- 文件名和大小，可修改的书名（默认去掉 .txt 扩展名）。
- 编码选择和分章方式。
- 章节总数、最多前 20 个章节标题及选定章节的短正文预览。
- 编码或分章可疑时的明确提示。
- 确认导入、取消；耗时阶段显示当前阶段及进度。

预览阶段不写入书架或正式正文目录。更改编码时重新解码原始字节，更改分章方式时重新解析。使用任务编号，忽略较早任务的返回结果；取消、重选文件或关闭面板要停止旧任务。重置文件输入，使取消后能够再次选择同一文件。

解析与写入阶段允许取消；进入不能中断的最终提交阶段后，明确显示“正在保存”，暂时禁止取消，并等待提交完成。不能通过直接关闭面板留下半本书。

支持现有最小窗口尺寸和主题，内容过长时面板内部滚动。原生文件选择器导致的焦点变化、取消或异常都要释放临时交互状态，保留窗口现有穿透和托盘规则。

TXT 内容始终作为纯文本处理：禁止 v-html、书源 JavaScript、网络引擎或 HTML 清洗器介入。原文中的尖括号和 HTML 实体应保留其文字含义。

## 5. 编码与纯解析模块

建议解析结果包含：

- encoding：最终使用的编码；
- text：完成 BOM 与换行规范化的完整文本；
- sections：每章的 title、start、end；
- splitMethod：标题识别或长度拆分；
- warnings：可展示的编码和分章提示。

start/end 必须统一为规范化 JavaScript 字符串中的 UTF-16 索引，end 为不包含位置；不能混用 UTF-8 字节偏移。解析模块不依赖 Vue、DOM、网络或持久化，便于单测。

### 5.1 解码顺序

1. 在读取大文件前检查原始大小，原生端超过 30 MiB（30 × 1024 × 1024 = 31,457,280 字节）拒绝并提示；恰好等于上限允许导入。浏览器环境的配额限制按第 6.2 节单独处理。
2. 先识别 UTF-8、UTF-16LE、UTF-16BE BOM。
3. 无 BOM 时优先严格 UTF-8 解码，失败后默认尝试 GB18030。
4. Big5 等无 BOM 编码存在歧义，不宣称能百分之百自动识别；预览乱码时允许用户手动切换。
5. 手动编码覆盖自动选择，并从原始字节重解码。解码失败给出明确提示，不默默丢失字符。
6. 仅移除文件开头 BOM，将 CRLF/CR 统一为 LF；不全局删空格、标点、重复段落或所谓广告。此处约束导入与存储；用户主动设置的净化在第 9 节显示阶段独立处理。
7. 空白文件拒绝。判断二进制或乱码时须考虑 UTF-16 的正常零字节，不能先把它误判为二进制文件。

不得把非空乱码视为识别正确；编码是否正确最终应让用户能通过预览判断。

### 5.2 分章识别

逐行扫描。标题识别可以使用去首尾空白、全角数字转换后的副本，但存储仍使用原始规范化文本及其偏移。候选标题建议不超过 80 字符，采用有边界、不会产生灾难性回溯的规则。

| 类型 | 支持示例与边界 |
| --- | --- |
| 中文主标题 | 第一章、第二百零三回、第 12 节、第１２章；允许正文前缀和合理空格 |
| 英文章节 | Chapter 1、CHAPTER XII，大小写不敏感，支持数字及罗马数字 |
| 特殊标题 | 序章、序言、前言、楔子、引子、尾声、后记、番外；需完整标题或合法分隔/编号，不能凭正文中出现该词触发 |
| 卷、部、篇 | 已识别章/回/节时不另制造空卷章节，卷标题保留在相邻正文；没有主章节时可作为分章依据 |

中文“章/回/节”和英文编号之后要求行尾或合理分隔符，例如空格、冒号、句点、顿号、短横线，避免把“第一章里说过……”误识别为标题。没有分隔的少数标题漏识别可以通过预览和长度模式处理，不为提高匹配率放宽到普通正文。

采用明确、可测的置信度规则并集中定义参数：

- 文件前部连续至少 5 个候选标题、之间没有实际正文时，视为疑似目录块，忽略这些分章点，但完整保留这些文字。
- 短文件开头只有一个合理标题可以成立。
- 长正文末尾孤立出现一个标题，不应把全书错误识别为前言加一章；回退长度分章并提示。
- 特殊标题仅作补充，不应凭孤立的“后记”等词断定整本书结构。
- 同名标题、重复章号、倒序章号均保留，不按名称或章号去重。
- 第一个有效标题前存在非空正文时，创建“前言”章节保存它。

以上位置比例、短文件长度和正文判定阈值应在实现中给出明确数值和测试，不隐藏在复杂正则里。

### 5.3 不丢正文与长度回退

所有章节区间必须按顺序连续覆盖 text 的全部内容：首段 start 为 0，相邻 end/start 相等，末段 end 等于 text.length。按顺序拼接全部章节内容，必须严格等于完成 BOM/换行规范化后的全文。不能吞掉标题、分隔符、卷名或尾部文字。

存储章节保留标题行；阅读器如要避免标题重复，只可在展示层省略已确认的首个标题行，不修改存储。只有标题的章节仍有内容，不能因此触发空正文错误。

无可靠章节或用户选择长度模式时：

1. 目标约 6000 字符，在约 4000～8000 范围内优先选择段落/换行边界。
2. 没有换行时寻找句末标点，再没有则硬切。
3. 切分不能拆开 UTF-16 代理对，分隔符须归属其中一段，不能丢失。
4. 标题使用“第 N 节”，并说明是自动分段，不冒充原书章节。
5. 很短且无标题的文本生成一个“正文”章节。
6. 标题识别产生的超长章也须按同类算法拆分，使用“原标题（1）/（2）”等名称，继续满足全文拼接不变。

### 5.4 响应性与资源释放

接近上限的文件不能长时间阻塞界面。优先使用 Worker，或分批处理并真正让出主线程；不能只在整个同步大循环前套一次延时。取消时终止任务并释放字节、全文、预览和章节切片引用，避免同时长期保留多份完整小说。

## 6. 本地书模型与持久化

### 6.1 兼容数据模型

Book 增加可选 origin，取值 remote 或 local-txt；旧数据缺失时一律按网络书处理。用统一的 isLocalBook 判定，不根据中文 sourceName、作者或书名推断。

本地书元信息建议包括 version: 1、contentHash、originalName、encoding、splitMethod、parserVersion、importedAt。正文不放入 library.json，也不放入普通响应式书架状态。

约定本地书 sourceUrl 为 local-txt，sourceName 为“本地 TXT”；bookUrl 和章节 URL 可以使用内部 local-txt:// 标识，包含应用生成的书 ID 和稳定章节 ID。它们只是内部键，禁止交给 fetch 或书源引擎。原始文件路径不作为阅读依赖，不拼进本地存储路径。

章节 ID 在导入时产生并保存，重启后从 manifest 读取，不重新解析生成。封面为空时沿用现有文字占位封面，不访问网络封面服务。

### 6.2 存储布局与读取

原生端建议使用 AppData 下：

    local-books/v1/<内部书ID>/manifest.json
    local-books/v1/<内部书ID>/chapters/000001.txt
    local-books/v1/<内部书ID>/chapters/000002.txt

manifest 保存版本、完整元信息和有序章节列表，正文为 UTF-8。内部 ID 和章节文件名须校验，不能允许输入文件名或 URL 控制目录穿越。只从 manifest 中经验证的章节记录读取文件。

平时只加载目录和当前章，不在打开书架时读取所有正文，也不重复存储完整原文件与全部拆分正文。

浏览器开发环境优先使用 IndexedDB 等能容纳目标文件的持久化。若复用 localStorage，必须明确较低的浏览器限制并处理配额错误，不能声称支持 30 MiB 完整导入；原生目标仍按本说明验证。

### 6.3 重复导入

使用正确解码、完成统一规范化后的全文计算稳定哈希。同内容不同文件名视为重复，提示并打开已有书，保留其进度；同文件名但不同内容允许导入新书。重复判断与最终提交应串行，不能两个任务同时漏过检查。

### 6.4 提交流程与失败恢复

建议顺序：

1. 完成预览与重复检查。
2. 为本次任务创建唯一临时目录。
3. 分批写入正文并报告已保存章数；正文均成功后写入完整 manifest。
4. 再检查取消状态。
5. 将完整数据提交为正式本地书目录。
6. 可靠持久化书架元信息，成功后才显示导入完成。

原有 library.save 是延迟调度，调用后不代表落盘；原有某些目录持久化调用会吞掉错误，不能沿用为成功判据。为导入提供能够等待和报告失败的提交路径。

必须处理“正式正文已落盘、书架保存失败”：保留可重试的完整数据，或执行经验证一致的回滚；不得留下指向已删除正文的书架记录。storage 的失败重试/待写队列也须纳入协调，防止回滚后旧写入又复活这本书。

取消或写入失败不改变已有书和进度，仅清理本次导入明确拥有的临时目录。不能扫描后广泛删除未知目录。对崩溃遗留的完整 manifest 与未登记书架的情况，提供受控的重试/恢复处理，避免静默覆盖同 ID 数据。

导入提交期间，删除或清空书架操作须等待任务或明确禁用，避免交叉写入。预览不进入持久化队列。

## 7. ReaderView 一次性接入方案

先把“取得目录/正文”与“展示正文/保存进度”分开，再在同一轮修改中接入两种来源、正文净化及点击行为。

### 7.1 目录加载与启动

现有 onMounted 会在找不到书源时直接报错；必须先判定本地书，本地书从 manifest 读取目录，不进入该书源判断。

ensureToc 本地分支读取本地目录，网络分支保留原流程及缓存。本地目录不能请求详情页或刷新网络目录。书架中本地书可以显示章节数和阅读进度，不展示虚假的在线更新状态。

### 7.2 正文加载

loadChapter 保留当前请求编号、销毁检查、取消/过期结果保护、加载和错误状态、恢复位置、成功后推进进度等机制。

本地书调用 localBooks 读取指定章节；网络书调用现有 engine.getContent。两者成功后进入相同的原文保留、全局净化、渲染和进度更新流程；细节遵循第 9 节。读取失败不得提前推进已读章节。

现有 renderedSource/章节 URL 的一致性检查要兼容本地来源；不能解引用不存在的 source。网络预取仅适用于网络书，首版本地书无须增加预取。

本地目录或正文缺失时显示本地文件损坏/缺失提示，提供适用的重试或重新导入指引；不要提示换网络书源。重导入同内容但已有记录损坏的恢复方式应明确，不能只被“重复导入”拦截而无恢复途径，也不能静默重置已有进度。

### 7.3 控件与共用行为

本地书隐藏换源、在线刷新目录、网络章节缓存入口及相关错误页操作。网络书保持原有按钮和行为。

保留同一套正文 DOM、目录跳转、上下章按钮、键盘操作、滚轮、阅读进度和设置。进度在正常滚动、点击滚动、返回书架、切章和退出时均按既有生命周期保存。

正文容器内已有末尾上下章按钮，点击这些按钮只能触发按钮自身动作，不能同时触发正文点击滚动。

## 8. 点击翻页实现细则

### 8.1 设置

在 AppSettings 类型、默认值和加载校验中加入 clickScrollEnabled: false、clickScrollLines: 5。开关仅接受合法布尔值，不能用 Boolean('false') 一类转换；行数只接受 1～30 的整数，无效值回退默认。

“设置 → 外观”在字号/行距附近增加开关和行数控件，关闭时禁用行数修改但保留值。说明：“点击正文上半区向上滚动，下半区向下滚动，每次约 N 行。”

数字输入允许临时空值编辑，提交或失焦时校验，不要用户尚未输入完就反复重置。也可使用整数滑块。设置立即生效并按现有机制保存，所有书共用。

### 8.2 点击区域与步长

以实际正文滚动容器 bodyEl 的当前可见内部区域为准，不包含标题栏、工具栏、边框和滚动条，不使用全文高度划分上下区。

每次有效点击时重新读取当前几何信息，使用 clientY 与 getBoundingClientRect 等同属 CSS 像素的坐标：

- 计算相对于正文内部可见区域的纵向位置，小于其高度的一半为向上，等于或大于中线为向下。
- 排除容器外侧、边框和滚动条区域，包括可能位于左侧的滚动条。
- 正文空白处可以点击，不添加覆盖正文的透明拦截层。

从实际正文段落或一致的正文样式读取当前计算行高，不使用章标题 h2 的行高。计算行高不可用时，使用已校验的当前字号乘行距作回退。

滚动距离 = 当前正文行高 × 设置行数。例如 18px × 1.9 × 5 = 171px。目标位置基于点击时实际 scrollTop，限制到 0～max(0, scrollHeight - clientHeight)，立即滚动，不叠加平滑动画。

段间距、标题等会影响视觉观感，因此界面描述为“约 N 行”，首版不要求逐行吸附或精确跨段落对齐。

### 8.3 缩放、改字号和调整窗口

正常窗口缩放、最大化/还原、字体大小、行距、内容宽度变化，以及 WebView 页面缩放，均纳入兼容范围：

1. 点击时重新测量容器和行高，不能只在挂载时缓存上下区分界或像素步长。
2. 窗口变矮后仍以新的正文中线判断方向，文字变大后仍按新行高滚动。
3. client 坐标、元素几何信息和 scrollTop 统一使用 CSS 像素；不要再次乘 devicePixelRatio、系统 DPI 或 WebView 缩放倍率。
4. 区分页面缩放和 CSS transform/zoom：当前正文若没有 CSS 变换，不引入变换方案；如果实际代码对祖先施加了缩放，必须先把视口坐标转换到正文布局坐标，不能直接混用缩放后的 rect 高度和未缩放的 clientHeight。
5. 从按下到松开期间若发生窗口尺寸、正文位置、字体或缩放变化，取消本次手势，避免区域移动后误翻页。
6. 布局变化可能触发滚动位置调整；应保护自动下一章判定，更新必要的滚动基线，不能把这种调整当成向下点击或主动滚动。复用现有恢复/布局状态，避免永久锁住滚动。

字体增大或窗口变窄会改变换行数，同样 5 行对应的原文字符数可以不同，这是预期行为。此功能不保证缩放后显示完全相同的那几句话，也不新增全文阅读锚点重构；应避免无关的进度重置和误切章。

### 8.4 手势、防误触与文本选择

只响应正文内的有效鼠标主键单击；忽略右键、中键、带修饰键的点击和键盘生成的模拟点击。

从实际目标向上检查交互元素，至少排除按钮、链接、输入框、选择框、可编辑区域及自定义交互控件；对末尾上下章按钮、错误页按钮尤其需要覆盖。

记录按下位置及手势全过程的最大移动量。建议超过 6 CSS 像素视为拖动，不能仅比较按下和松开终点，因为用户可能拖动后回到原位。pointercancel、容器外释放、窗口失焦和切换阅读对象均清理手势；滚动条操作及窗口拖动/缩放不算正文点击。

按下时已存在正文选区，或松开/点击时正文存在非折叠选区，都不滚动。不得在按下时 preventDefault，保留原生拖选、复制及上下文菜单。

首版采用“单击立即滚动、双击/三击的后续 click（detail > 1）不滚动”的取舍。第一次单击可能已滚动，因此不能承诺双击选词时正文绝对静止；如要完全避免，必须另做延迟单击方案，本次不默认加入。

对应测试和文案须一致：普通独立点击以当前位置继续滚动；系统识别为双击/三击的后续点击不保证每次累加。不要同时要求“所有快速连点逐次翻页”和“双击只选文字完全不翻页”。

### 8.5 边界与进度

- 顶部向上点击不动，不自动上一章。
- 自动下一章关闭时，向下到末尾停在本章。
- 自动下一章开启时，仅点击导致实际向下滚动到末尾，交由现有滚动入口切到下一章一次。
- 已经在底部再点击、短正文不足一屏、最后一章，都不新增跳章逻辑。
- 向上点击即使仍处于底部阈值附近，也不能触发下一章。
- 成功改变 scrollTop 后及时保存当前位置，保留既有 scroll 保存机制；仅改变位置的函数不可兼任切章。
- 点击触发切章后，新正文仍由现有请求保护和恢复流程接管。离开页面后不得有延迟手势、旧任务或计时器继续操作新书。

## 9. 全局替换净化规则

### 9.1 功能范围与默认行为

新增用户可管理的“正文净化”功能，用于替换或删除广告、网址提示、求票语、重复声明等用户明确指定的非正文文字。规则全局共用，同时作用于网络在线正文、已下载的离线缓存和本地 TXT；不按书源或书籍复制规则。

默认总开关关闭、规则列表为空，不内置自动启用的广泛删除规则。新增规则默认启用，但需要保存且总开关开启才实际应用。首版支持普通文本和正则表达式两种模式；不支持执行 JavaScript、联网下载规则、自动识别广告或修改原文件。

作用范围仅为当前章节正文。书名、作者、简介、目录标题、正文独立的章节标题控件不参与替换。TXT 存储正文中的标题行仍可能命中用户规则，但不会因此改动 manifest、章节 ID 或目录结构。“全局”同时表示规则适用于所有书，以及每条规则替换当前章内的全部非重叠匹配；不跨章匹配，不扫描整本书批量改写。

### 9.2 管理入口与使用流程

在阅读页工具栏增加“净化”入口，窄窗口可置于已有更多菜单；在设置中提供同一规则面板的入口。面板显示“规则对全部书籍正文生效，原文保留，可随时关闭”。

需要提供：

- 总开关、规则列表及逐条开关。
- 新增、编辑、删除、上移/下移调整顺序；排序说明为“从上到下依次执行”。
- 规则名称、匹配模式、查找内容、替换内容；替换内容允许为空，表示删除。
- 普通模式默认区分大小写；正则模式提供忽略大小写、多行匹配、点号匹配换行选项，默认关闭。
- 保存、取消、当前章预览；编辑使用草稿，取消不改变已保存规则，也不实时修改阅读正文。
- 预览显示原文与处理后文本的有限片段、各规则命中次数和错误。没有打开章节时允许粘贴少量测试文字；不为预览读取所有缓存或整本 TXT。
- 当前章“查看原文/恢复净化”入口，不修改总开关和规则。此临时状态只作用于当前章节，切书或切章后恢复正常全局设置。

预览与实际应用必须使用同一套规则顺序、选项和处理器。当前章预览应基于完整章节计算，界面只限制展示长度，避免仅用截断样本却报告整章命中次数；粘贴测试模式要明确标为样本文本。

可在正文存在有效选区时显示“加入净化规则”操作，将所选文字填入普通文本规则草稿，仍由用户预览并保存。选区跨出正文或超过查找长度限制时提示，不自动截断后创建规则。操作按钮必须排除点击翻页；不重写原生右键菜单、不自动把任意文本选择保存成规则。

规则面板纳入现有弹窗、键盘及点击互斥处理。输入正则或按上下方向键编辑时不能触发切章，关闭面板的点击不能穿透正文。

### 9.3 匹配与替换语义

1. 按列表顺序执行启用规则。后一条读取前一条处理后的结果；每条只执行一轮全局替换，不对自己刚插入的文字继续递归匹配。
2. 普通模式按字面量匹配全部非重叠片段，不把句点、括号、星号或反斜杠解释成正则。
3. 正则模式直接填写表达式，不填写两侧斜杠；内部固定全局与 Unicode 模式，再叠加允许的 i/m/s 选项。禁止任意传入其它标志。无效表达式须在保存前提示。
4. 首版两种模式的替换内容都按字面量处理，包括 $1、$& 等字符，不展开捕获组；界面明确“不支持分组引用”。实现应使用字面量替换回调等方式避免意外解释。后续如需捕获组替换，另行扩展并迁移语义。
5. 查找文本为空时禁止保存；不得对查找或替换内容 trim，因为空格和换行可能就是用户目标。规则名称可以去首尾空白。
6. 查找和替换使用支持真实换行的文本框。普通模式中的反斜杠 n 就是两个字符；正则模式按表达式解释。输入框 CRLF/CR 统一为 LF，执行前正文也统一换行，但不回写存储。
7. 删除广告后不额外自动删段落、合并空格、转换简繁体或执行 HTML 解码；规则之外的文字保持不变。最终显示沿用正文已有的段落排版。
8. 零宽正则匹配可以保留标准的向前推进语义，但必须有终止和输出上限；若手动统计匹配次数，不能写出遇到零宽匹配不前进的循环。
9. 命中次数按各规则在当时输入中的匹配次数统计，不把所有次数简单等同于“删除段落数”；跨行替换和不改变文本的匹配也要保持一致定义。

示例（仅供理解或手动添加，不默认启用）：

| 模式 | 查找 | 替换 | 效果 |
| --- | --- | --- | --- |
| 普通文本 | 请收藏本站，方便下次阅读。 | 留空 | 删除所有完全相同的提示语 |
| 普通文本 | 错别字示例 | 正确文字 | 替换全部完全匹配的文字 |
| 正则，多行开启 | ^[ \t]*【本站提示】[^\n]*(?:\n\|$) | 留空 | 删除以明确提示标记开头的整行 |

上表正则中的竖线在 Markdown 表格里用反斜杠转义显示；编辑器实际输入为正则的“或”符号。不要提供无边界的“删掉所有包含收藏/作者/网址的段落”作为默认规则，避免误删正常叙事。

### 9.4 持久化模型与处理模块

建议单独使用 src/stores/purification.ts，持久化到 purification-rules.json，结构包含 schemaVersion: 1、enabled 和有序 rules 数组。每条规则包含稳定 id、name、enabled、mode（text/regex）、find、replacement 和三个正则选项布尔值；数组顺序即执行顺序，避免同时维护互相矛盾的 order 字段。

全局配置只保存一处，不同时把列表写入 settings.json。设置面板和阅读面板共用该 store。文件缺失按关闭及空列表处理；读入时校验版本、字段类型、ID 唯一性和长度。损坏配置或无效规则要提示并隔离，不让阅读器启动失败，也不能静默覆盖用户可恢复的原配置/备份。

规则保存采用现有可靠写入与 flush 机制，面板显示保存失败并允许重试；不要把仅更新内存称为保存成功。同一批修改串行提交，避免旧写入覆盖新规则。总开关和单条开关同样需要持久化失败反馈。读取完成前不要把默认空规则自动写回文件。

建议新增 src/services/textPurification.ts 与相应 Worker：输入为当前章原正文和规则快照，输出为净化正文、规则命中统计及明确的错误/超限结果。纯匹配逻辑与 UI、文件系统、书源引擎分离，便于测试。运行期维护规则版本号，保存、启停或排序后递增，不必把临时任务编号写入配置。

### 9.5 原文、缓存与 TXT 分章的边界

统一数据流：

    网络引擎/离线缓存或本地章节文件
      → rawContent（本次全局净化前的正文）
      → 应用已启用的全局规则
      → displayContent
      → 段落渲染、点击滚动与进度

网络 rawContent 指书源引擎按原有流程提取后的文字，不保证是网页原始 HTML，也不撤销书源本身已有的清洗。TXT rawContent 来自完成 BOM/换行规范化的本地章节。

必须保留 rawContent 与 displayContent 的区分。每次重新计算都从 rawContent 开始，不对上一次净化结果继续套规则。保存 TXT、网络缓存、后台预取和批量缓存任务均不应用本次全局净化；缓存内容、键和有效性不能随规则改变。

TXT 导入分章、偏移、哈希去重、导入预览和全文拼接测试仍以净化前文本为依据。因此本章不与“不丢正文”约定冲突，也不能借净化改写目录。导入预览标注为原文；实际阅读时再应用规则。

规则变化对当前章重新计算，其它章节下次打开时应用。无需重新下载、清空缓存或重新导入 TXT；不为了全局生效批量加载所有书。若缓存派生显示结果，键至少包含书 ID、来源与章节标识、原文版本、规则版本和原文查看模式，避免换源或编辑规则后串用旧结果。

### 9.6 性能、异常与取消

用户正则可能极慢。正则执行和预览必须位于可终止 Worker 内，不能在 Vue computed 或主线程中直接执行未知正则；主线程 Promise.race 超时不能中断同步正则，不能当成已解决卡顿。

首版建议限制：最多 100 条规则；每条查找不超过 2000 个 UTF-16 单元，替换不超过 10000 个；样本文本最多 50000 个。超过限制明确提示，不静默截断配置。

Worker 就绪后，主线程对单章整批净化设置约 1500ms 的执行超时，并有独立的 Worker 初始化超时。执行超时直接 terminate，取消或重新计算同样要能终止旧任务。阈值集中配置并测试，在原生环境有证据时可调整；不能用静态正则检查代替执行保护。

对替换膨胀设置输出上限，建议不超过 max(1000000, 原文长度 × 4) 个 UTF-16 单元，按输出片段累计时检查，不能先拼出巨大字符串再检查长度。统计和预览亦受相同时间、长度约束。

发生非法规则、Worker 不可用、超时或输出超限时，本章整批结果作废，回退本章原文并显示“净化未完成，正在显示原文”，提供管理规则/重试入口；不展示半套规则的结果，也不自动删除或永久禁用用户规则。能定位规则时显示其名称，无法定位时不要乱报。

相同规则版本发生超时后，本阅读会话暂时暂停自动净化并持续显示可见状态，避免每切一章都卡一次；修改规则或手动重试后恢复。该运行期暂停与持久化总开关区分。取消旧任务不作为用户可见的执行失败。

切书、切章、换源、编辑规则、切原文模式或退出后，旧 Worker 结果必须被请求编号和来源/规则版本校验丢弃。成功、失败、取消都释放 Worker、定时器和大文本引用。

### 9.7 与进度、点击翻页及空正文的协调

首次加载章节时，先取得 rawContent 并按现有逻辑校验，再完成净化或原文回退，最后渲染并恢复阅读比例。净化过程纳入 loading/restoring 或等效状态，不让空白过渡期保存错误进度。

在当前章保存/启停/重排规则，或切换查看原文时：

1. 捕获当前有效阅读比例和章节身份，冻结进度保存及自动下一章，清除点击手势。
2. 从 rawContent 重新计算；等待最新结果和正文布局完成。
3. 在新滚动范围按原比例恢复并限制到有效区间，更新 lastScrollTop。
4. 确认请求仍有效后解锁。净化导致内容缩短、浏览器自动夹紧 scrollTop 时不得误触发下一章。

比例恢复保证不重置整本书进度，但不保证大量删改后还停在相同句子；首版不扩展精确文本锚点。点击步长始终按净化后实际显示的正文行高计算，显示内容重排后重新测量。

rawContent 非空但净化后只剩空白时，这是“本章内容已被净化规则全部隐藏”，不是书源加载失败、TXT 损坏或可重新下载的空缓存。显示专门提示、查看原文、管理规则以及仍可用的手动上下章按钮；点击空白不自动换章，不自动跳过连续空章。

全隐藏状态不覆盖已保存的有效阅读比例；恢复原文或修改规则后用该比例恢复。手动切章仍能正常记录章节进度。此处须调整现有仅根据 content/paragraphs 判断是否展示按钮或保存进度的条件。

### 9.8 退出与规则草稿

已保存规则纳入应用现有退出 flush。真正退出时终止净化与预览 Worker，这些派生结果不需要持久化，不能阻塞窗口销毁；已经开始的规则配置写入则需要等待并处理失败。

未保存草稿不自动变成正式规则。面板用保存/取消处理，关闭有修改的草稿时提供一次保存或放弃选择；真正退出复用该决策，不反复弹窗。隐藏到托盘不等于放弃草稿，保持现有窗口行为。


## 10. 删除、清空与真正退出

删除一本本地书只删除应用内部副本，不操作原 TXT 文件。确认文案说明内部副本会删除。删除和清空的按钮应等待异步完成并捕获错误，不能未成功就报告完成。

清空书架包含其管理的本地书内部数据；清空书源不包含本地书。删除过程中保证书架元信息与正文一致，失败提供重试，不留下仍可见但无正文的书。任何清理都限定到经验证的本地书内部目录。

真正退出时：

1. 保存当前阅读进度并阻止新导入。
2. 取消解析/预览和可取消写入，等待清理；已进入最终提交的导入则等待完成或失败。
3. 协调并等待现有章节缓存任务停止。
4. 刷新待写、失败重试和书架等存储；有失败时保留错误提示及可恢复状态。
5. 成功后按原流程销毁窗口。

协调器应放在能被退出入口访问的服务层，不能只依赖 TXT 弹窗或 ReaderView 的卸载钩子。pagehide 只能作为尽力保存的补充，不能作为可靠完成异步导入的唯一保证。

现有元信息导出并不包含本地正文。本次不新增完整备份；若触及相关代码/文案，要避免把书架元信息误称为 TXT 完整备份。

## 12. 回归测试与验收

沿用项目实际测试框架和脚本，不另造一套重复测试设施。测试验证用户行为及关键数据不变量，避免只断言实现函数被调用。

### 12.1 TXT 解析自动测试

覆盖：

- UTF-8 有/无 BOM、GB18030、Big5 手动选择、UTF-16LE/BE；CRLF/CR、中文标点、emoji。
- 中文数字/阿拉伯数字/全角数字标题、英文和罗马数字标题、特殊标题、卷章混排。
- 标题前前言、重复标题和编号、疑似目录块、普通正文假标题、长文本末尾孤立标题。
- 无标题、无换行、超长单章、仅标题、仅空白、空文件、异常输入和大小超限。
- 原生端文件大小边界：31,457,279 和 31,457,280 字节通过大小检查，31,457,281 字节在读取前拒绝；另验证文件内容有效性，不将通过大小检查等同于导入必然成功。
- 所有分章模式中区间连续、正文拼接严格相等、无代理对截断。
- 取消和重选后的旧结果不覆盖新预览。

### 12.2 持久化与生命周期自动测试

- 导入后销毁并重建服务/状态，读取持久化目录与正文；不能仅依赖同一进程内缓存证明可重启。
- 原文件不可用时仍可读取；同内容异名去重保留进度，同名异内容可导入。
- 临时正文写失败、manifest 写失败、正式提交失败、书架保存失败、失败队列重试、取消、重复提交、退出中提交。
- 验证已保存书和进度不受失败导入影响，失败重试不会复活已回滚的无正文书架记录。
- 本地书在无任何书源时可启动阅读，读取正文不调用网络引擎或 fetch。
- 删除/清空只清理目标内部数据；清源不删除 TXT；网络缓存清理不触及 TXT。
- 有损坏记录时，重新导入或恢复路径可以实际完成，不能因去重陷入死路。

### 12.3 点击与联合自动测试

在 DOM 无实际布局的测试环境中显式模拟 rect、clientHeight、scrollHeight、scrollTop 与计算样式；不能将模拟布局测试当作原生窗口验证。

覆盖：

- 默认关闭；开启后上下方向、中线归下、1/5/30 行、配置非法值及重载保存。
- 依据正文可见区域判断方向；滚动条、边框和容器外不触发。
- 更改容器大小、字号、行距后下一次点击使用新值；按下与松开期间变更布局取消手势。
- 拖选、已有选区、拖出再返回、右/中键、修饰键、失焦、pointercancel、双击后续 click。
- 正文内按钮只执行自身行为，弹窗关闭不穿透，加载/恢复/错误/幽灵状态不翻页。
- 顶部、底部、短正文、最后一章、自动下一章开/关，以及向上点击不误切章。
- 普通独立点击与方向切换按当前位置计算，无动画积压。
- 点击后立即返回或退出，重新进入恢复进度。
- 网络在线、网络离线缓存、本地 TXT 三种正文均使用同一点击行为。
- 点击触发下一章期间关闭或切书，旧异步结果不能写入新阅读状态。
- 缩放或恢复位置引发的 scroll 不自动切章；正常主动向下滚动仍能切章。

### 12.4 正文净化与三功能联合测试

- 默认无规则且关闭；新增、编辑、启停、排序、删除、保存失败与重启恢复；取消草稿不生效，两个入口使用同一配置。
- 普通文本字面量匹配、全部非重叠替换、空替换删除、多行输入、查找空格不被 trim；普通/正则替换中的 $1、$& 均保持字面量。
- 正则大小写、多行及点号跨行选项；零宽匹配可终止、无效表达式提示；多条顺序执行但单条不递归替换。
- 预览与实际结果/次数一致；完整章计算但限制显示片段；规则输出始终以纯文本渲染。
- 网络在线、网络持久化缓存、TXT 的相同正文得到相同净化结果；编辑规则后不发起重新下载。
- 原文、TXT manifest/分章偏移/哈希及网络缓存未被改写；禁用全部规则能恢复全局净化前正文。
- 恶劣正则的真实 Worker 超时终止、取消、输出膨胀上限、Worker 不可用和会话暂停；不能仅 mock 超时就宣称不卡界面。
- 失败整批回退原文，规则仍保留；切书/章/来源/规则版本后过期结果不污染页面，重复计算不把规则叠加到旧结果。
- 全隐藏提示与原始正文为空的错误区分；查看原文可恢复；手动切章可用；不会自动跳过章节或把原文缓存标坏。
- 净化后高度改变、规则开关、原文查看、窗口缩放与点击翻页组合下，进度比例保留，布局变动不误触发自动下一章。
- 规则面板与选区操作不触发点击翻页或快捷键切章；正在净化时离开页面，任务、指针和定时器正确清理。
- 配置损坏不覆盖可恢复文件；退出等待已提交写入，处理未保存草稿，终止派生任务；托盘隐藏不丢草稿。
