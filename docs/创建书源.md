# 透读：创建自己的书源

适用于当前项目 0.2.0。示例全部使用虚构页面或项目内生成的本地小说。

书源是一份 JSON 配置，用来告诉阅读器四件事：到哪里搜索、从结果里取哪本书、怎样取得目录、正文在哪个元素内。它不是万能抓取器；不同页面结构需要不同规则。

## 先运行一个确定可用的示例

1. 在项目目录打开终端，运行 `node scripts/fixture-server.mjs`，保持终端运行。
2. 打开透读 → 设置 → 书源。
3. 在网络导入框中填 `http://127.0.0.1:1422/sources.json`，点击“网络导入”。它提供两份本地测试书源。
4. 搜索“山间来信”，点击阅读。可切换 A/B 来源，测试目录、正文和换源续读。

也可以打开 `sources/local-example.json`，复制全部内容，粘贴进书源文本框，再点“粘贴导入”。该文件只包含 A 源，同样需要启动本地测试服务。示例服务总是返回同一本书，用来验证规则，不实现真正的关键词检索。

桌面版不需要启动 `npm run dev`。若测试浏览器界面，另开终端运行 `npm run dev`。浏览器与桌面版使用不同的数据存储。

## 复制模板

复制 `sources/template.json` 为自己的文件，用文本编辑器修改。模板采用保留的虚构域名，默认 `enabled: false`；修改并验证后改为 `true`。

必须使用合法 JSON：属性名和字符串用双引号，不写注释，最后一个字段后不加逗号。

| 字段 | 填写内容 |
| --- | --- |
| `bookSourceName` | 在应用中显示的名称 |
| `bookSourceUrl` | 书源标识及相对网址的基础地址，应保持稳定 |
| `bookSourceType` | 文本小说填 `0` |
| `enabled` | 修改完成后填 `true` |
| `searchUrl` | 搜索请求地址，`{{key}}` 会替换为已进行 URL 编码的关键词 |
| `ruleSearch` | 搜索结果中的书名、链接、作者等 |
| `ruleBookInfo` | 可选；详情页信息，以及独立目录页的入口 |
| `ruleToc` | 章节列表、章名、章节链接 |
| `ruleContent` | 正文容器及可选的正文分页链接 |

## 用一组教学页面理解规则

下面的 HTML 只是说明模板的匹配关系，不代表某个真实网站。

### 1. 搜索结果

```html
<div class="search-results">
  <div class="book-item">
    <a class="book-title" href="/book/1">山间来信</a>
    <span class="book-author">作者：林间</span>
    <img src="/covers/1.jpg">
    <p class="book-intro">一封来自山间的信。</p>
    <span class="book-kind">小说</span>
  </div>
</div>
```

对应模板中的规则：

```json
"ruleSearch": {
  "bookList": ".search-results .book-item",
  "name": ".book-title@text",
  "author": ".book-author@text##^作者[：:]\\s*##",
  "bookUrl": ".book-title@href",
  "coverUrl": "img@src",
  "intro": ".book-intro@text",
  "kind": ".book-kind@text"
}
```

`bookList` 先找到每本书的容器，其他字段在每一个容器内部查找。`.book-title@text` 取显示文字，`.book-title@href` 取链接。作者规则末尾的 `##` 替换会去掉“作者：”前缀。

### 2. 详情页与目录入口

```html
<div class="book-info">
  <h1>山间来信</h1>
  <span class="book-author">作者：林间</span>
  <img src="/covers/1.jpg">
  <p class="book-intro">一封来自山间的信。</p>
  <a class="toc-link" href="/book/1/chapters">完整目录</a>
</div>
```

模板的 `ruleBookInfo.tocUrl` 使用 `a.toc-link@href`，得到独立目录页地址。如果详情页本身就包含完整目录，可以删除整个 `ruleBookInfo`，应用会从书籍链接读取目录。

### 3. 章节目录

```html
<div class="chapter-list">
  <a class="chapter" href="/chapter/1">第一章 初见</a>
  <a class="chapter" href="/chapter/2">第二章 风起</a>
</div>
```

```json
"ruleToc": {
  "chapterList": ".chapter-list a.chapter",
  "chapterName": "@text",
  "chapterUrl": "@href",
  "nextTocUrl": ""
}
```

这里选中的列表项已经是 `<a>`，所以直接写 `@text` 和 `@href`。目录应按阅读顺序排列，选择器要避开推荐书、返回首页和导航链接。

### 4. 正文

```html
<h1>第一章 初见</h1>
<div id="content">
  <p>清晨的山路笼着薄雾。</p>
  <p>远处传来溪水的声音。</p>
</div>
```

```json
"ruleContent": {
  "content": "#content",
  "nextContentUrl": "",
  "replaceRegex": ""
}
```

正文优先写容器选择器 `#content`，不加 `@text`。当前引擎会把段落和换行标签转成纯文本换行；直接取 `@text` 可能把段落粘在一起。

## 常用规则速查

| 规则 | 含义 |
| --- | --- |
| `.book-item` | 匹配 class 为 book-item 的元素 |
| `#content` | 匹配 id 为 content 的元素 |
| `.chapter-list a` | 匹配目录容器中的链接 |
| `a@text` | 取链接文字 |
| `a@href` | 取链接地址，自动解析相对路径 |
| `img@src` | 取图片地址 |
| `img@data-src` | 取保存在 data-src 属性里的图片地址 |
| `@text` / `@href` | 取当前列表项的文字或链接 |
| `.intro@text##^简介：##` | 去掉结果开头的“简介：” |
| `@css:p:eq(1)>a@text` | 按 Jsoup/Legado 位置取第二个段落中的链接文字 |
| `//div[@id="list"]//a` | 无前缀 XPath，列表子规则会限定在当前项目内 |
| `:href="([^"]+)">([^<]+)` | AllInOne 正则列表；子规则用 `$1`、`$2` 读取捕获组 |
| `规则A%%规则B` | 按下标交错合并两个列表 |
| `{{java.encodeURI(key)}}` | 将搜索关键词进行 URL 编码 |
| `{{(page-1)*20}}` | 计算页码相关的偏移量 |

当前已覆盖教程中的常用 Default、CSS 位置、XPath、JSONPath、AllInOne/OnlyOne、连接符、URL 请求选项及基础 JavaScript 规则。依赖 WebView 渲染、登录交互、验证码、完整 CookieJar、原生 Android/Java API、`@put/@get` 跨规则传值或未实现 Java 方法的书源仍需改写。

## 创建流程

1. **准备页面样本**：为普通文本内容准备搜索结果、详情、目录、正文的 HTML 样本。优先使用自己控制的页面或明确允许使用的内容。
2. **填写搜索地址**：例如模板的 `/search?q={{key}}&page={{page}}`；`q` 和 `page` 只是示例参数名，并非所有网站都相同。
3. **填写搜索规则**：先保证能获得书名和有效书籍链接，再填写作者、封面和简介。
4. **填写目录规则**：确认解析出来的是章节链接，并按正确顺序排列。
5. **填写正文规则**：只选择正文容器，检查段落是否正常，是否混进导航或广告。
6. **导入与验证**：复制完整 JSON → 设置 → 书源 → 粘贴框 → 预览 → 导入选中。至少测试两本书、连续两章，以及退出阅读后重新打开。

模板里的 CSS 类名必须换成目标页面实际使用的类名。若页面样本里根本没有正文，仅有脚本加载的空容器，静态 CSS 规则就无法获得正文。

## 分页怎么填

仅在页面确实存在分页时设置相应字段：

- `ruleToc.nextTocUrl`：指向同一本书的下一页目录，例如教学页面中的 `a.toc-next@href`。
- `ruleContent.nextContentUrl`：指向同一章的下一页正文，例如教学页面中的 `a.content-next@href`。

**不要把“下一章”按钮填成正文分页。** 下一章由阅读器控制；填错会把多章正文拼在一起。末页应不再匹配到有效的下一页链接。

当前最多抓取 20 页目录、10 页正文；超出上限不会自动读取更多。搜索从第 1 页开始，滚动到底部或点击“搜索下一页”后，`{{page}}` 会依次变为 2、3……，最多请求 20 页；已经取得的同书结果仍会合并去重。

## 导入后修改与排错

当前相同 `bookSourceUrl` 的重复导入会被跳过，不会覆盖旧规则。修改自己的书源时，保留 JSON 原稿，在设置中移除同地址的旧书源，再导入新版；保持 `bookSourceUrl` 不变，书架仍能通过该标识找到新规则。已经缓存的目录需要在阅读页点击“目录 → 刷新”。

| 现象 | 优先检查 |
| --- | --- |
| 没有可用书源 | `enabled` 是否为 true、类型是否为 0 |
| 搜索无结果 | 搜索地址、参数名、bookList、书名及书籍链接选择器 |
| HTTP 错误或超时 | 地址是否有效、页面能否正常访问 |
| 目录为空或混进导航 | 是否需要独立目录地址，chapterList 是否选得过宽 |
| 正文为空 | 正文是否在返回的 HTML 中，content 是否命中容器 |
| 正文跨了多章 | nextContentUrl 是否误选“下一章” |
| 段落挤成一行 | 正文规则是否误用了 @text |
| 修改后没变化 | 是否因重复导入被跳过，目录缓存是否已刷新 |
| 浏览器预览失败但桌面正常 | 浏览器跨域限制；本地教学服务已允许跨域 |

当前项目不支持完整登录流程、验证码交互、复杂 Cookie 会话，也不会运行网页本身的渲染脚本。这些页面不能仅靠填写这个静态模板完成适配。

## 验证随附模板

在项目目录运行：

```powershell
node scripts/check-source-examples.mjs
```

该命令使用本地构造的页面，通过项目真实的导入解析、搜索、详情、目录和正文引擎检查两份配置；不会访问外部站点。
