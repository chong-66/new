# 透读：章节缓存功能实现说明

编写日期：2026-09-10。依据当前项目 v0.1.3 的实际代码编写，供 GPT-5.6 接手实现。

**本文是待实现方案，章节缓存功能尚未开发。此次工作只新增本说明书，不修改程序、不打包、不发布。**

## 1. 用户需求与实现边界

用户原话：“加一个功能，可以缓存章节，可以自己控制缓存多少章。”

实现目标：在阅读页填写章数，批量保存当前小说的指定范围正文；退出程序、重新打开并断网后，仍能阅读保存成功的章节。保留原有阅读进度、书源规则、托盘和窗口行为。

下文的默认 50 章、范围从当前章开始、串行下载等，是本说明书建议的产品选择，不是用户另外提出的要求。可直接按此实现，无需为这些常规选择再次询问用户。

首版不做多本书后台队列、定时更新、自动缓存整本、云同步或代理配置。书源 403 是独立问题；缓存只能保存能够正常取得的正文，不能解决接口拒绝访问。

两个容易遗漏的问题：

1. `library.setToc()` 当前吞掉写入失败。内存里有目录不代表重启后有目录，不能因此宣称“离线缓存成功”。应让该方法返回可靠的持久化结果，或提供专门的 `persistToc` 方法让缓存任务等待并接收异常；原有阅读失败提示保持合理。
2. 内存正文键当前没有 `book.bookUrl`，只有书源地址、章节地址、正文规则、请求头和 `jsLib`。接入时补足书籍上下文，避免某些依赖 `book` 的规则串书。

## 3. 用户操作与显示规则

### 3.1 缓存入口

阅读页顶部“换源 / 目录”附近增加“缓存”按钮，打开抽屉或小面板。无书源、无目录或目录仍在加载时禁用开始按钮，显示原因。适配窗口最小尺寸 420 × 320，面板内容可滚动。

建议界面内容：

```text
缓存章节                           关闭
从当前第 12 章开始，包含当前章
缓存章数  [ 50 ]   [10] [50] [100]
本次范围：第 12～61 章，共 50 章
本书当前书源已缓存：8 章

[开始缓存]

缓存中：20 / 50
新保存 15 章 · 已有 4 章 · 失败 1 章
正在缓存：第 32 章 ……
[停止缓存]
离开阅读页会停止任务，已保存章节会保留。
```

- “50 章”表示从开始时当前章起的连续 50 章范围，**包含当前章**。范围内已有本地正文则跳过，不向后补齐 50 个新章节。
- 不超过剩余目录长度。例如总共 101 章，从第 95 章缓存 50 章，实际范围第 95～101 章，共 7 章；开始前显示这个范围。
- 输入必须是有限的正整数；空值、0、负数、小数及非数字不启动任务。设置载入时校验历史值，非法值回退为 50。不要把合法的超范围输入悄悄变成全书下载。
- 开始时冻结书源、书籍上下文、目录范围。期间翻页不会改变下载范围，也不会增加未选章节。
- 一次只运行一个任务，运行时禁止重复开始或修改范围；停止后可以修改数量并重新开始。
- 已处理数 = 新保存数 + 已有数 + 失败数；只有持久化成功才能计入“新保存”。取消的在途章节不算失败。
- 关闭缓存面板继续下载；再次打开能看到进度。返回书架、切换书籍、开始换源或刷新目录则停止任务，已完成部分保留。
- 同一范围再次启动时跳过已保存部分，相当于继续缓存。首版无需持久化任务队列或重启自动续传。
- 目录项显示简短“已缓存”标记，以章节 URL 匹配，不用章节序号判断。
- 缓存面板打开时，屏蔽阅读翻页快捷键、滚动自动下一章和正文字号滚轮；输入框保留正常编辑行为。Escape 优先关闭面板，不能意外返回书架。

可选增强：提供“清除本书缓存”。不是首版完成的必要条件；如果实现，必须遵守第 4 节删除与写入互斥要求，并准确显示清理失败。

## 4. 持久化存储设计

### 4.1 推荐布局

新增 `src/services/chapterCache.ts`，负责保存、读取、列举和清理正文，不负责抓取网页。桌面使用 Tauri AppData，建议结构：

```text
chapter-cache/v1/<bookKey>/<sourceKey>/<chapterKey>.json
```

键用 SHA-256 等确定性摘要生成；序列化键的输入使用数组，避免字符串拼接歧义。所有磁盘目录、文件名都由内部生成，不能直接拼接书源里的 URL、书名或导入的 book.id。

- `bookKey`：书架 `book.id` 的摘要，便于删除本书所有来源的缓存。
- `sourceKey`：`[source.bookSourceUrl, book.bookUrl]` 的摘要；换源后保留同一个 `book.id`，也不会读到原来源正文。
- `chapterKey`：完整 `chapter.url` 的摘要；保留查询参数，不能自行删除可能代表章节或语言的参数。

每个记录保存 `version`、`sourceUrl`、`bookUrl`、`chapterUrl`、`title`、`content`、`savedAt`，读取时校验版本、身份字段和非空正文。缓存最终解析并净化后的完整纯文本，不能保存网页、验证页面、空字符串或分页中的半章内容。

首版可以用目录中的正式文件名集合生成目录缓存标记，无需另外维护一份不断重写的全书正文索引。文件名标记表示“存在缓存记录”；读取校验失败时撤销该标记并按未缓存处理。忽略 `.tmp` 文件。

不把整本小说塞进 `library.json`、`settings.json`，也不每下载一章就重写已下载的全部正文。避免几百章时产生大量重复写入和全书内存占用。

### 4.2 与现有 JSON 存储的关系

正文是可重新下载的独立数据，建议使用缓存专用存储逻辑：同一键串行写入，先写临时文件再替换正式文件，维护在途写入集合并暴露等待接口。不必为每章保留 `.bak`，也不必沿用全局设置的失败自动重试队列。

这是为了避免清除缓存后 `flushStorage()` 又把失败队列中的旧正文写回来，或 `readJson()` 自动从 `.bak` 恢复已清除内容。若选择复用现有服务，必须补齐删除时清理 pending / queues / failed / backup 的完整语义，不能只删除主文件。

缓存写入失败要抛出异常给任务，显示“保存失败”，并停止继续下载，防止磁盘不足时持续请求。失败不能破坏之前有效的正文。读损坏记录可以作为未命中处理；读到不存在的记录属于正常情况。

浏览器预览用相同逻辑键的独立 localStorage 前缀，测试也走这个后端。浏览器容量较小，超额写入必须明确报错，不能拿浏览器缓存能力代替桌面文件缓存验收。

删除书籍时先停止该书任务，等待在途写入结束，再删除其派生缓存目录。若实现清空书架，逐一处理被清理的书籍。删除范围必须限定于缓存根目录；不能删除 AppData 根目录。仅修改来源规则时保留已经明确下载的离线正文，用户可以强制刷新；这是有意的产品语义。

现有能力文件已经声明 AppData 递归读写范围。实现后实际验证所用 `mkdir/readDir/readTextFile/writeTextFile/rename/remove` 的操作权限；缺什么补最小权限，不扩大为任意路径访问。

## 5. 正文读取和下载任务

### 5.1 统一正文读取

继续以 `engine.getContent()` 为阅读和批量缓存共用入口，防止两套解析逻辑产生不同正文。服务依赖方向保持单向：引擎依赖缓存存储；下载任务依赖引擎和缓存存储；缓存存储不反向导入引擎。

普通阅读的建议顺序：

1. 检查取消信号。
2. 检查显式保存的持久化正文，再查内存 LRU；命中直接返回。
3. 未命中时按现有方式联网、执行书源规则、处理分页及净化。
4. 正常阅读只更新内存 LRU；**只有用户开启缓存任务才新增持久化正文**，使用户选择的章数有明确含义。

内存键保留现有规则、请求头和 `jsLib` 区分，并补上书籍 URL；持久化键按第 4 节设计，规则编辑不会使旧离线正文突然消失。清理或刷新持久化缓存时同步失效对应内存条目。

`force: true` 明确跳过持久化和内存缓存，重新获取正文。若该章此前属于离线缓存，网络成功后原子更新它；网络或保存失败不能先删掉旧版离线正文。普通未缓存章节的强制刷新仍只进内存。

命中本地正文应足够快，不能先等待在线探测。未缓存且网络失败时显示该章未缓存及实际网络错误，不把任何网络异常都断言成“已断网”。本次范围不要求在删除书源后仍能打开小说，书源记录及目录保留即可。

### 5.2 下载任务

建议新增 `src/services/chapterCacheTask.ts`，提供可测试的任务控制器和进度回调，界面只绑定状态与按钮。首版不必新增全局后台队列或把正文放到 Pinia。

执行顺序：

1. 校验书籍仍在书架、来源一致、目录非空和数量合法；生成不可变范围快照。
2. 可靠地保存当前目录；失败则终止，避免缓存正文却没有可离线导航的目录。
3. 对范围内章节顺序处理：检查取消 → 校验已有持久化记录 → 有效则跳过 → 否则调用 `getContent` → 再查取消 → 等待正文保存成功 → 更新进度。
4. 新网络章节之间安排约 300 毫秒可取消间隔，已有章节不延时。默认并发为 1，不自动重试同一失败请求。
5. 单章解析失败、普通请求失败可记录并继续；403、429 或连续 3 章网络/解析失败则停止，保留原因。磁盘保存失败立即停止。可给 HTTP 层添加带 `status` 的错误类型，同时保持现有中文错误信息；不要用所有错误都重新请求的策略。
6. 完成、停止或失败后，保留本次成功 / 跳过 / 失败计数及简短原因。更换书籍后不能把旧状态或错误提示写到新书界面。

任务有独立 `AbortController`，与阅读的 `chapterController`、`tocController`、`prefetchController` 分离。开始任务时取消下一章预取，运行中不再启动预取；用户手动翻页仍可正常加载，翻页不取消任务。批量缓存不调用 `loadChapter`、`updateProgress` 或 `updatePosition`，否则会把阅读位置改到最后下载章节。

首版允许用户阅读与下载偶尔请求同一章，不必为此引入复杂的全局请求共享。若实现去重，必须让不同调用方的取消相互独立，不能取消下载就连带打断正在阅读的正文。

### 5.3 生命周期和真正退出

- 停止后不启动下一章。当前网络请求和等待间隔应响应取消；已经开始的文件写入可以完成，但必须等待并正确保留，不能留下半个正式文件。
- 返回书架、换书、换源、刷新目录和组件卸载时停止旧任务。取消不能依赖关闭面板。
- 任务拥有自己的书籍 / 来源快照；不要反复读取会被 `library.changeSource()` 原地改写的响应式对象。
- 隐藏到托盘不是退出，下载继续。真正退出时先禁止新缓存任务、取消在途任务，等待必要的文件写入，再执行原有 `flushStorage()` 和窗口销毁。
- 不要只在 `onBeforeUnmount` 取消：当前托盘退出会直接销毁原生窗口，不保证 Vue 先卸载。可提供小型活动任务注册表供 `tray.ts` 的保存回调调用停止并等待。
- 如果保存失败使窗口继续打开，要解除“退出中”的启动锁，让用户能恢复操作。不要为了缓存改变关闭按钮或托盘菜单原有含义。

## 7. 验收标准

自动测试优先使用固定假书源和伪造响应，不依赖第三方在线服务。可扩展现有 `scripts/test.mjs`，或新增 `scripts/check-chapter-cache.mjs` 并接入 `npm test`。

| 场景 | 必须成立 |
| --- | --- |
| 数量和边界 | 第 12 章开始选 50，只选第 12～61；尾部自动截断；非法数量不开任务 |
| 已有缓存 | 范围内已有 4 章则跳过这 4 章，不向范围外补下载；进度统计相符 |
| 超过内存上限 | 保存至少 35 章，销毁并重新创建模块/应用环境，保留存储、禁用网络；第一章和最后一章都能读，证明不是依赖 30 条内存 LRU |
| 离线完整路径 | 保存目录与正文后重启断网，从书架进入并通过目录切换已缓存章；未缓存章给出明确错误 |
| 进度保护 | 从第 12 章缓存到第 61 章，读者没有翻页时阅读进度与滚动位置仍是第 12 章 |
| 取消 | 下载第二章时停止，不开始第三章；第一章重启仍可读；取消不计失败 |
| 关闭面板 / 翻页 | 面板关闭仍继续，重开状态正确；翻页不会改变任务范围 |
| 换书 / 换源 | 相同章节地址在不同书籍或来源下不串正文；迟到的旧请求不更新新界面或新来源缓存 |
| 持久化故障 | 模拟目录保存失败、正文磁盘满 / localStorage 超额；不报成功、不继续批量请求、不破坏旧缓存 |
| HTTP 失败 | 403 / 429 停止并展示原因；普通单章失败按策略处理；取消信号传播到底层 |
| 刷新与损坏 | 强制刷新绕过两层缓存；失败保留旧正文；损坏记录不作为有效正文返回 |
| 写入与删除竞态 | 删除本书后迟到的任务不重建目录；其他书籍及书架设置不受影响 |
| 托盘及退出 | 收起窗口继续任务；真正退出先停止任务、等待写入；保存失败时窗口保留且可继续操作 |
| UI 回归 | 最小窗口布局可用；输入数量不翻页，Escape 先关闭面板；暗色、亮色和护眼主题可读 |
